# 分工

| 角色 | 谁 | 负责 |
|---|---|---|
| 定方向、出样板 | 云端 Claude | 设计、Blender 建模规范、每类零件 / 机构 / 效果的第一个样板、声音、世界观、最后一道审查 |
| 难的铺开 | Codex · sol 档 | 照样板用 Blender 脚本建复杂零件（鳞片瓦阵列、变形关节、座舱细节）、需要判断力的大改动；Claude 额度紧时可顶上做部分样板 |
| 简单的铺开 | Codex · 普通档 | 调参数、重出片、改文档、跑检查 |
| 独立审查 | 没参与制作的 Claude 子代理 | 截图对照概念图、叠图与目标帧，按 VISUAL_TARGET 清单逐项打分；自己不改，只报告 |
| 多模态审查（可选） | Gemini Argon | 额度不足（作者 2026-10-15），只在作者主动转交时用：听成片、看视频节奏（规则见 `GEMINI.md`） |
| 概念图 | GPT | 新机体、新场景的多视角概念图 |
| 拍板 | 作者 | 每个阶段门禁 |

一个分支只归一个 AI：`claude/…`、`codex/…`、`gemini/…`；合入 main 前由 Claude 审、作者确认。

# 分工细则：Claude 云端会话 × Codex

原则：**难的、决定成败的部分由 Claude 云端会话做；定型之后大量重复的调整交给 Codex。** 判断标准是“这件事需不需要看着画面做审美判断、需不需要定下新的做法”——需要的归 Claude；只是照着已定好的做法批量铺开、反复微调数值的归 Codex。

## Claude 云端会话负责（最难的部分）

| 工作 | 为什么归 Claude |
|---|---|
| 几何母版：剪影、体积、曲面拆分、比例校准 | 要对照照片反复做外形判断 |
| 视觉风格样板：明暗、线条分级、投影、取景、材质 | 决定“像不像 A380 那种质感”，全靠看图判断 |
| 渲染路线决策（Anatomy 3D 或 Three.js） | 牵一发动全身 |
| 每类机构的“第一个样板”：例如第一扇舱门、第一个喷管的完整开合 | 定下零件拆分、轴心、动作过程的做法 |
| 装配树与状态架构：`airframe` 根组、关节注册、SceneState / ActionDirector 核心 | 后面所有交互都建在它上面 |
| 第一条完整演出（垂直起飞）及中途干预的混合逻辑 | 最复杂的时序与因果 |
| 写“做法说明”交给 Codex（见下文） | 把审美和规则固化成可照做的清单 |

## Codex 负责（定型之后的重复工作）

| 工作 | 前提 |
|---|---|
| 按已定样板，把同类机构铺开到其余零件（其余舱门、对侧零件、起落架各组） | Claude 已在 `docs/PATTERNS.md` 写好该类做法 |
| 按已定规则批量补细节（铆钉行、口盖锯齿边、拼缝） | 同上 |
| 大量数值微调：动作时长、缓动、偏转角、颜色、线宽、灯光强度 | 作者给出具体要改什么 |
| 其余快捷演出（左转、右转、降落等）照第一条演出的结构扩写 | 第一条演出已通过作者确认 |
| UI：底部三排控制台、手机抽屉、纯净模式、画质档 | 视觉样板已定 |
| 性能优化、真机/多浏览器测试、bug 修复 | 不改几何母版和视觉规则 |
| 截图、录屏、导出素材 | — |

## 交接方式

1. Claude 每完成一类样板，就在 `docs/PATTERNS.md` 追加一节：做法、参考实现的文件与函数、验收截图、常见错误。
2. 在 `docs/ROADMAP.md` 里把可以交给 Codex 的任务标成 `[Codex]`，并写清楚照哪一节 PATTERNS 做。
3. Codex 只在功能分支上工作，读 `AGENTS.md`；不得修改 `src/geometry/` 的几何母版和 `docs/PATTERNS.md` 里定下的规则——发现规则有问题，写进 `review/` 的 SUMMARY 里，由作者转给 Claude 处理。
4. 作者在中间传话和验收：Claude 交样板 → 作者确认 → Codex 铺开 → 作者抽查。

## 什么时候把活收回给 Claude

- Codex 连续两轮改不对同一处画面问题；
- 需要新增一种之前没有样板的机构或效果；
- 改动会影响几何母版、视觉规则或状态架构。
