# 分工

| 角色 | 谁 | 负责 |
|---|---|---|
| 定方向、出样板 | 云端 Claude | 设计、Blender 建模规范、每类零件 / 机构 / 效果的第一个样板、声音、世界观、最后一道审查 |
| 难的铺开 | Codex · sol 档 | 照样板用 Blender 脚本建复杂零件（鳞片瓦阵列、变形关节、座舱细节）、需要判断力的大改动；Claude 额度紧时可顶上做部分样板 |
| 简单的铺开 | Codex · 普通档 | 调参数、重出片、改文档、跑检查 |
| 独立审查 | 没参与制作的 Claude 子代理 | 截图对照概念图、叠图与目标帧，按 VISUAL_TARGET 清单逐项打分；自己不改，只报告 |
| 多模态审查（可选） | Gemini Argon | 额度不足（作者 2026-10-15），只在作者主动转交时用：听成片、看视频节奏（规则见 `GEMINI.md`） |
| 概念图 | GPT | 新机体、新场景的多视角概念图 |
| 拍板 | 作者 | 每个阶段门禁 |

一个分支只归一个 AI：`claude/…`、`codex/…`、`gemini/…`；合入 main 前由 Claude 审、作者确认。

# 分工细则：Claude 云端会话 × Codex

原则：**难的、决定成败的部分由 Claude 云端会话做；定型之后大量重复的调整交给 Codex。** 判断标准是“这件事需不需要看着画面做审美判断、需不需要定下新的做法”——需要的归 Claude；只是照着已定好的做法批量铺开、反复微调数值的归 Codex。

## Claude 云端会话负责（最难的部分）

| 工作 | 为什么归 Claude |
|---|---|
| 几何母版：剪影、体积、曲面拆分、比例校准 | 要对照照片反复做外形判断 |
| 视觉风格样板：明暗、线条分级、投影、取景、材质 | 决定“像不像 A380 那种质感”，全靠看图判断 |
| 渲染路线决策（Anatomy 3D 或 Three.js） | 牵一发动全身 |
| 每类机构的“第一个样板”：例如第一扇舱门、第一个喷管的完整开合 | 定下零件拆分、轴心、动作过程的做法 |
| 装配树与状态架构：`airframe` 根组、关节注册、SceneState / ActionDirector 核心 | 后面所有交互都建在它上面 |
| 第一条完整演出（垂直起飞）及中途干预的混合逻辑 | 最复杂的时序与因果 |
| 写“做法说明”交给 Codex（见下文） | 把审美和规则固化成可照做的清单 |

## Codex 负责（定型之后的重复工作）

| 工作 | 前提 |
|---|---|
| 按已定样板，把同类机构铺开到其余零件（其余舱门、对侧零件、起落架各组） | Claude 已在 `docs/PATTERNS.md` 写好该类做法 |
| 按已定规则批量补细节（铆钉行、口盖锯齿边、拼缝） | 同上 |
| 大量数值微调：动作时长、缓动、偏转角、颜色、线宽、灯光强度 | 作者给出具体要改什么 |
| 其余快捷演出（左转、右转、降落等）照第一条演出的结构扩写 | 第一条演出已通过作者确认 |
| UI：底部三排控制台、手机抽屉、纯净模式、画质档 | 视觉样板已定 |
| 性能优化、真机/多浏览器测试、bug 修复 | 不改几何母版和视觉规则 |
| 截图、录屏、导出素材 | — |

## 交接方式

1. Claude 每完成一类样板，就在 `docs/PATTERNS.md` 追加一节：做法、参考实现的文件与函数、验收截图、常见错误。
2. 在 `docs/ROADMAP.md` 里把可以交给 Codex 的任务标成 `[Codex]`，并写清楚照哪一节 PATTERNS 做。
3. Codex 只在功能分支上工作，读 `AGENTS.md`；不得修改 `src/geometry/` 的几何母版和 `docs/PATTERNS.md` 里定下的规则——发现规则有问题，写进 `review/` 的 SUMMARY 里，由作者转给 Claude 处理。
4. 作者在中间传话和验收：Claude 交样板 → 作者确认 → Codex 铺开 → 作者抽查。

## 什么时候把活收回给 Claude

- Codex 连续两轮改不对同一处画面问题；
- 需要新增一种之前没有样板的机构或效果；
- 改动会影响几何母版、视觉规则或状态架构。

## 从概念图到模型：中间加「拆图」一步（作者 2026-10-15）

GPT 的图好看但不能直接建模（视角、比例、视图之间都有偏差），建模时边看边猜，返工多。所以每张要复刻的参考图，建模前先变成数据：

| 步 | 谁 | 产出 |
|---|---|---|
| 0 · 建模用图 | 作者（GPT 图片编辑） | 在原图上编辑出一张**分色块面图**：同构图、同位置，去掉文字、编号、发光和明暗，零件按类别填纯色（提示词见 `docs/IMAGE_PROMPTS.md`「建模用图」）。与原图 50% 叠图检查，偏移明显就不用，退回只用原图 |
| 1 · 标定 | Claude | 每张参考图旁一个 `<图名>.calib.json`：至少两个已知点（如光窗中心、座舱盖前缘）→ 像素/米、原点、视图方向。之后一切量取都经它换算 |
| 2 · 拆图 | Claude（分色图可自动提取：按颜色找连通块 → 包围盒） | `<图名>.parts.csv` 零件表：编号、名称、类别、站位 s、y、z、长宽高、基本形（盒 / 柱 / 管 / 板 / 人体）、材质、固定在哪个零件上、来源图、把握度（高 / 中 / 猜）。缺的那一维（侧剖缺 y）从配对视图取，没有就标“猜” |
| 3 · 拆图叠图 | Claude → 作者扫一眼 | 把零件表画成彩色框叠回原图：一张图就能看出“理解得对不对”。在这一步改，比在模型上改便宜得多 |
| 4 · 建模 | Claude 做样板，Codex 照零件表铺开 | 几何母版按零件表生成，参数化零件库补管线和支架；完成后与原图叠图验收（VISUAL_TARGET「复刻标准」） |

补充：
- **触发方式**（作者 2026-10-15 定）：每个阶段开工前，Claude 把这一阶段要用的分色图列给作者——哪张原图（仓库路径）+ 用 `docs/IMAGE_PROMPTS.md`「建模用图」里的哪一段（A 内部 / B 外形 / C 人物）；作者去 GPT 出图发回，Claude 叠图标定后推进仓库。
- 内部图尽量**成对**：侧剖（x、z）配俯视剖（x、y）或横剖（y、z），同一比例；只有一张时缺的一维标“猜”。
- 人体（飞行员）不用基本形拼：用开源人体基础网格（许可证须为 CC0 或同等宽松，引入前写进 `THIRD_PARTY_NOTICES.md`）按身高和坐姿摆好，服装按 X1 分层套在外面。
- 外形轮廓（C2 / C3 的俯、侧、前视）同样标定后自动提取剪影折线，直接作为放样截面的依据。

## AI 起稿：Tripo（作者 2026-10-15 定）

**用在哪**：有机形体和“看着对就行”的东西——銜燭的人体与服装、头盔底稿；中精度 / 占位区里形状复杂但不需要精确尺寸的小件（座椅坐垫、握把、脐带接头之类）。
**不用在哪**：烛龙外形母版、化剑转轴与收拢件、烛心、任何要叠图复刻或要按轴运动的硬表面。理由：AI 网格不对称、看不见的一面靠猜、没有可抓的精确棱和轴，每次重生成都会漂。

| 步 | 做法 |
|---|---|
| 1 · 喂图 | **只喂单个主体的裁图**（整张设定图会被做成一整版小人）。裁图从仓库原图按框裁出、补成方图，存为 `refs/ai_draft/<图名>_输入.png` |
| 2 · 生成 | 人体 / 服装：HD Model · H3.1 · AI Complete 开 · Generate in Parts（Balanced）· 不带贴图 · 约 30 万面。硬壳件（头盔、甲片）：Smart Mesh · P2.0 · Quad · 5000～10000 面 |
| 3 · 导出 | GLB（四边面要保留时导 FBX）。存 `refs/ai_draft/`，附 Workbench 检查图和一行结论（README 表格） |
| 4 · 锁版 | 挑一版满意的**锁定**，之后一律在 Blender 里改这一版，不回 Tripo 重生成 |
| 5 · 精修 | 缩放到设定尺寸 → 对称 → 看不见的一面按看得见的一面补齐 → 硬件锐化（重做棱、分缝）→ 拆出要单独运动的件（面罩等）→ 磨掉乱码字 → 换我们的材质 → 骨架 |

规矩：
- **许可**：免费版生成的模型不可商用、且对外可见。测试随便用；**要发布的那一版在付费版（Pro 起）里按同样输入和参数重新生成**，再走第 4、5 步。
- 输入图只用我们自己的原创设定图；生成结果同样按“不仿现有 IP”审一遍（头盔尤其）。
- Claude 可以在作者登录后的浏览器里直接操作 Tripo（上传裁图、设参数、导出），导出文件经作者电脑的下载文件夹取回云端。
