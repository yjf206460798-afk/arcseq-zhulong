## 引擎与作品分开（Z0 定）`[kit]`

- 适用于：一切代码改动先判断它属于引擎还是作品。
- 参考实现：
  - 引擎（与机型无关）：`src/figure/engine/NN-*.js`（浏览器端，按文件名顺序拼进同一个闭包、共享作用域：`00-setup` 渲染器与相机 → `10-materials` 明暗材质 → `20-model` 零件与关节 → `30-lines` 线条 → `40-deck` 转台、投影、灯 → `50-state` 机构状态 → `60-director` 演出 → `70-fx` 尾焰 → `80-post` 后处理 → `90-page` 环境、交互、审图入口）；`engine/pack.mjs`（取景 `fitView`、凸包打包 `packHulls`、页面拼装 `engineScript` / `pageHtml`）；`engine/glb.mjs`（GLB → 零件）；`src/figure/weld.mjs`、`shots.mjs`、`aa.mjs`、`perf.mjs`、`scripts/chrome.sh`、`scripts/strip.py`。
  - 作品：`src/figure/build.mjs`（几何来源、配色卡、材质表、线条、特效、环境、机构、演出、文字）、`blender/`（几何母版）。
- 规则：引擎文件里不出现机型专有名词（零件名、地标名只经 `DATA` 传入）；作品要新能力时，先在引擎里做成数据驱动的通用功能（例：`lineLevel`、`glow`、`accent`、`environments.backdrop`），再在 build.mjs 里填数。改引擎时在提交说明里写“引擎：……”。
- 常见错误：在引擎里写 `if (part.name === "…")`；把作品数值写进引擎（数值一律进 build.mjs 的 `FX` / `POST` / `LINES` / `ENVIRONMENTS`）。

## 几何母版：Blender 建模脚本（Z1 定）

- 适用于：一切机体零件。母版是脚本：`blender/build.py` + `blender/zl/*.py`，运行一次从零生成全部模型；`assets/zhulong.glb`、`.json`、`zhulong-skin.png` 是产物（提交进仓库，网页构建不需要 Blender），`.blend` 只在 `--blend` 时另存到 `dist/`。
- 命令：`.venv/bin/python blender/build.py`（建模 + 烘焙 + 导出，约 3 分钟：建模 4 s、烘焙 180 s）；`--fast` 只看形（约 4 s，写到 `dist/fast/`，不覆盖 assets；预览页 `node src/figure/build.mjs --assets=dist/fast --out=dist/fast/index.html`）；`--render-only out.png [--shot hero|nose|cutaway] [--power 0|1]` 出 Cycles 渲染（不改 assets）。装法见 `docs/BLENDER.md`。
- 模块：`blender/zl/nose.py`（外形）、`interior.py`（剖视内部，对 K1）、`section.py`（剖面带、穿模自检）、`bake.py` / `detail.py`（烘焙与细节贴图）、`render.py`（Cycles）；零件库 `blender/kit/`（见「参数化零件库」）。
- 步骤：
  1. 坐标与网页相同：米，x 前、y 左、z 上，原点在转台轴心；站位 s 自机头尖向后，`at(s, y, z)`（`zl/util.py`，x = 9.5 − s）。
  2. **命名即接口**：每个零件一个对象，对象名 = 网页零件名；左侧 `.l`，右侧用 `mirror_object` 镜像出 `.r`（自定义属性照抄，记得改 `skin` / `joint`）。
  3. **自定义属性即元数据**（导出 `export_extras`，网页原样并进零件）：`skin`（线条蒙皮组，同组之间不出接缝线；机身蒙皮一律 `"skin"`）、`joint`、`system`（`"void"` 空腔）、`glass`、`glow: { key, color }`（自发光，见「选择性发光」）、`lineLevel: "secondary"`（细密重复件的线一律降为 L2：鳞片瓦、虹膜片）/ `"structure"`（内部件封顶 L1）、`shadow: false`（不进投影）、`module: "interior"`（按需模块）、`show`（`"cutaway"` / `"!cutaway"`）、`cut`（剖视时被剖切面切开）、`curved`（曲面件，网页按曲面轮廓取线）。材质槽名 = 网页材质表键（`hull` / `belly` / `carbon` / `glass` / `interior` / `sensor` / `void`）。
  4. 两个零件要“长在一起”、交线要成为真实折边的（眉骨、背部整流并进机身），用 `boolean(target, cutter)`（EXACT 并）；要单独成件、交界出一级结构线的（座舱盖、滑轨、鸭翼），单独成对象、底部嵌进机身 1～3 cm。
  5. 分割线、棱线、地标、遮线区写进 `meta`（→ `assets/zhulong.json`）：`seams` 用 `surface_point(s, facet, t, lift)` 在切面上取点、抬 2 mm、带法线；`level` 为 `"secondary"`（L2）/ `"structure"`（L1）/ `"accent"`（朱红棱线）。
  6. 改完跑 `node src/figure/build.mjs`，再截图（`scripts/z1-review.sh` 里有现成的命令）。
- 验收：四方位线稿里新零件不悬空、不穿插；4× 特写里交线清楚；`build.py` 输出的三角形数不超过预算（`docs/BLENDER.md`）。
- 常见错误：薄片零件离蒙皮只有几毫米、又在 20 cm 以内被线的深度让出量透出来（加 `masks`，见眼珠）；忘了镜像件的 `skin`（左右两件同名蒙皮组，中间的接缝线消失）；`--fast` 以为会更新 assets（不会）。

## 切面机身：单顶点棱锥（Z1 定，复刻样板按 C2 实测改）

- 适用于：烛龙机身、以及之后一切“大块精确切面”的蒙皮。
- 参考实现：`blender/zl/nose.py` 的 `K` / `APEX_S` / `ring` / `surface` / `facet_normal` / `body`。
- 步骤：
  1. 截面只用几条棱：R0 背脊、R1 朱红脊线、R2 棱线（最宽）、R3 腹缘，腹底平面 R3–R3′；从背脊顺时针依次是屋面、外上切面（C2 里那条暗带）、下切面（鳞片瓦）、平腹底。
  2. **一段只有一个顶点**：每条棱都是汇向顶点（机头前 0.35 m）的直线，站位 s 处 R = (a·t, Z_TIP + b·t)，t = s − APEX_S；a、b 直接从 C2 三视图量（俯视 66 px/m、侧视 42.4 px/m、前视 46.7 px/m）。这样每张切面严格是平面——平面着色不出斜纹，五档明暗在一张切面上是一整块。
  3. 需要折的地方（背脊在 s 6.4 之后放平）换一段，接缝处折角 < 22° 不出线，只是明暗一档的变化。
  4. 切面上的细分（站位每 0.1 m、横向 2～4 格）只为顶点 AO 有足够的顶点，不改形状。
- 验收：叠图（见「复刻标准」）里外轮廓与 C2 偏差 ≤ 2 像素；体积模式下同一切面是一块均匀的色。
- 常见错误：两站截面各自给值、直线插值（相邻两条棱线不共面，切面变成扭曲面，平面着色出三角斜纹）。

## 画面链：多重采样、超采样、选择性发光（Z1 定）`[kit]`

- 适用于：一切画面输出。参考实现：`src/figure/engine/80-post.js`（`sizePost`、`renderFrame`、`renderAll`、`backdrop`）；数值在 build.mjs 的 `POST`。
- 做法：
  1. 场景画进多重采样离屏缓冲（`POST.msaa` = 4，带深度纹理）；网页高画质档在 DPR < 2 的屏上按 `POST.ssaa` = 2 倍画、合成时盒式下采样；手机标准档不超采样。
  2. **只让发光部件发光**：发光量是零件的属性（`glow: { key, color }`）乘通电量（`powerOf(key)`，由机构的 `power` 键驱动）。有东西在发光时，同一场景按“发光通道”再画一遍进半分辨率缓冲：带状材质只输出自发光、其余写黑但照常挡深度；朱红 accent 线层画发光色；普通线、光点、尾焰、投影不画。这张图两级模糊后叠回画面（`POST.bloom`）。所以亮的蒙皮不会泛光，被机体挡住的发光件也不泛光。
  3. 新发光件：几何母版里写 `glow`，build.mjs 的 `CONTROLS` 里加一个 `power: "<key>"` 的机构；不要在材质里直接调亮。
- 验收：`QA-glow-off/on`：未通电时画面与没有发光完全一样；通电后只有烛光窗与朱红棱线有晕，晕不超过线宽的十几倍。
- 常见错误：把发光做成材质颜色调亮（会被当成蒙皮的一档明暗，且不泛光）；发光缓冲不清黑。

## 线条的精确覆盖（Z1 定，抗锯齿）`[kit]`

- 参考实现：`30-lines.js` 的 `LINE_FRAG`：覆盖率 = 像素（宽 1）与线（宽 2·vHalf）在法向上的重叠长度（一维盒式滤波的精确积分）。
- 为什么：细于 1 像素的线（L1 0.5 px、L2 0.42 px）落在两个像素之间时，两像素覆盖率之和恒等于线宽，转动时亮度不随亚像素位置起伏。FIG.01 的近似式在 0.42 px 线上约 ±15% 起伏。
- 三级线宽（R3 起，作者要“三级读得出来”）：L0 外轮廓 0.9 px / 不透明 0.78、L1 结构 0.55 / 0.6、L2 工艺 0.35 / 0.3。内部件默认封顶到 L1；最大边长不到 5 cm 的小件（螺栓、接头、卡箍、铭牌）在 `interior.build()` 里一律降为 L2，剖面带与外形轮廓是 L0。
- 验收：`node src/figure/aa.mjs <目录>`：0.1° 一步慢转 8 帧、与 4× 超采样参照逐像素比（只算边缘与线条像素）。Z1 实测：FIG.01 式 2.85 / 闪烁 2.01 → 精确覆盖 0.87 / 0.94 → 加 2× 超采样 0.35 / 0.45（`AA.txt`）。

## 线条分级在着色器里（Z1 复刻样板 R4 定）`[kit]`

- 参考实现：`30-lines.js` 的 `LINE_VERT` / `lineLayer()`。每条边是一个实例（`InstancedBufferGeometry`，基础几何是 4 个角 + 索引），实例属性：两端点 `aA/aB`、两侧面法线 `aN1/aN2`、边类 `aKind`（0 缓边、1 折边、2 蒙皮组接缝、3 只有一侧面的边、4 分割线 / 口盖线）、权重、沿线位置。每层一个材质、一个 draw call。
- 顶点着色器按当前视向（每层一个 `uView`，换到零件坐标系）判出 外轮廓 L0 / 结构 L1 / 工艺 L2 / 不画，不画的实例整块挪到裁剪空间外；`uCap`（封顶级别）、`uDemote`（整层降一级）、`uLow`（低画质不画工艺线）、`uCreaseDown`（折边降一级）是层级开关。JS 每帧只写几个 uniform。
- 为什么：R3 每帧在 JS 里逐条定级、重写索引，剖视时 24 万条边在手机档要 19 ms；挪进着色器后同一测法（390 / DPR 3 / 4× 节流、剖视稳定转动）每帧脚本 30.8 → 14.0 ms。这是 three.js 粗线（Line2）同一类做法，真 GPU 上几十万个 4 顶点实例是常规负载；云端软件 GL（SwiftShader）逐实例处理很慢（剖视一帧约 6 s，R3 约 0.5 s），只影响截图耗时，不代表真机——真机 GPU 发布前实测。
- 剖视内部件的折边降一级（`creaseDown`：`module === "interior" && lineLevel === "structure"` 的件），离剖切面越远线越淡（`lineDepthFade`，与材质的 `uDepthFade` 同开同关）。
- 常见错误：在 JS 里再按视向筛一遍实例（要重传实例缓冲，比着色器判还慢）；忘了每层的 `uView` 要换到该层父节点坐标系（关节件转动后线级会错）。

## 顶点 AO 与烘焙细节贴图（Z1 定，复刻样板扩充）

- 参考实现：`blender/zl/bake.py`（`vertex_ao(objs, hide=)`、`detail_texture(objs, meta, assets, hide=)`）、`blender/zl/detail.py`（`paint`、`segment_field`、`rivets_along`、`value_noise`、`decal`、`dilate`）；网页 `10-materials.js` 的 `aAO`、`uDetail`、`uDetailMid`、`uPbrMap`。
- 做法：
  1. 顶点 AO：Cycles 烘到每个零件的颜色属性 `ao`（导出为 COLOR_0），只看 45 cm 以内。外形与剖视内部分两次烘，互相 `hide`（内部件不给蒙皮烘出暗斑，蒙皮也不给内部压暗——剖视时近侧蒙皮是切掉的）。空腔薄片与贴面件（`aoOccluder: false`）不当遮挡物。
  2. 细节贴图 `zhulong-skin.png`（机身蒙皮 2048²，按角度展 UV → 烘每个纹素的世界坐标、法线、AO → numpy 程序生成）：
     - **r 明度乘子，0.5 = 不变**（`mid: true`，网页按 `2·r` 乘）：刻线（分割线两侧 4 mm 浅槽，压暗约 25%）、铆钉（沿分割线两侧各一行、35 mm 一颗）、腹底蜂窝缝（与下切面几何瓦同一套 `HEX_W × HEX_H` 格子，按 `ZONES` 分区，区间留 1.5 cm 分区缝）；**面板错拼 ±3%**（按 `meta.panel_cuts` 的环缝站位 × 切面 × 左右编号哈希）；**棱边磨损**（母版硬边 1.2 cm 内、值噪声断续、只提亮 ≤ 3%）。
     - **g 涂装**：机号「02」、「燭龍 ZHULONG」（铭文一律繁体，DESIGN 8.5）、姿控喷口警示三角。**b** 贴图 AO。
  3. B 画法另一张 `zhulong-skin-pbr.png`：rgb 物体空间法线（刻线成槽、铆钉成小圆顶，用到线段 / 点的距离场求离线方向）、a 粗糙度（面板 ±0.05、刻线更糙、磨损更光）。只进 B 版页面。
  4. 细节疏密：铆钉、涂装只在已有结构旁；安静区靠 ±3% 错拼与 L2 细线，不留空白也不撒花。新增涂装改 `detail.py` 的 `paint`，不手画贴图。
- 验收：`CLOSE-*-4x-*`（铆钉行、口盖、机号可读）、1× 不抢眼；`skin.png` 的 r 通道均值 ≈ 128。
- 常见错误：浮点烘焙图的 alpha 判断有效纹素（要用法线长度）；贴着蒙皮的薄片参与 AO；r 通道按旧的“只压暗”编码（≤ 1）写，面板就只能变暗。

## 朱红棱线（accent 线，Z1 定）

- 参考实现：几何母版 `seams` 里 `level: "accent", accent: "chine"`；引擎 `30-lines.js` 的 accent 层；数值 `LINES.accents.chine`。
- 规则：线宽同主描边（0.75 px），色 `#c8412c`（偏暗不荧光），未通电只亮 `idle` = 0.38；机构 `chine`（通电量）与 `chine.sweep`（0…1 沿线从机头扫到末端，前沿多一小段亮）一起驱动；通电后进发光缓冲（发光色 `#ff5a32`）。化剑“开锋”在 Z5 用同一对机构。
- 常见错误：用材质色画朱红（转到背面也亮、不会扫）。

## 环境与背景（Z1 定）`[kit]`

- 参考实现：`90-page.js` 的 `setEnvironment` / `backdropSpec`、`80-post.js` 的 `backdrop`；数值 `ENVIRONMENTS`。
- 规则：机库段 `hangar`（R3 起：深蓝黑竖向渐变 `#152029 → #0a0f13`，不用纯黑；剖视里机身空腔的暗内壁也偏蓝 `#141c21`）；太空 / 天门段 `space`：机体压暗 `dim`、台面更暗、背景两端渐变 + 稀疏星点（5 像素一格的哈希，星约 1 像素，不画光芒）+ 地球弧（屏幕坐标里的大圆、一条细的大气辉线 + 很淡的外晕，弧顶正好从转台边缘后面升起）。入轨演出用 `environment(name, mix)` 在两者之间过渡（Z5）。

## 电影画质（录制模式，Z1 定，网页版不开）`[kit]`

- 参考实现：`80-post.js` 的 `renderCinemaFrame`、合成着色器里的景深与调色；审图入口 `__arcseq.cinema(opts)`、`__arcseq.cinemaFrame({ dt, spin })`。
- 四项：超采样 `ssaa`（2～4）；**真实运动模糊**（一帧快门内推进 `blur` 个子帧，每个子帧完整走一遍 `advance` 再画，在半浮点缓冲里平均——转台、机构、尾焰都按真实运动模糊）；**特写景深**（`dof: { focus: 模型坐标点, range 米, coc 像素 }`，正交相机深度线性，泊松盘 16 点、按样本自己的弥散圈加权）；**调色**（暗部偏冷亮部偏暖、以 0.18 为支点的轻 S、暗角、1 LSB 颗粒；数值 `POST.grade`）。
- 用法：录制脚本先 `cinema({...})`，然后每帧 `cinemaFrame()`；截图用 drive 的 `shot`（不要再调 `view()`，它会按网页版重画）。
- 常见错误：景深范围太窄（机头一米外全糊，朱红线也糊掉）——机头特写 range 取 1.5～2.5 m。

## 复刻标准：叠图对位（Z1 复刻样板定）

- 适用于：一切“对 refs 的图一比一复刻”的部位（VISUAL_TARGET「复刻标准」）。外形对 C2 / C3，内部对 refs/layout 的 L0、E1～E4、K1。
- 参考实现：`scripts/overlay.mjs`（叠图）、`scripts/replica-review.sh`（整轮交审）、`scripts/replica-sheets.py`（拼图）；页面 `__arcseq.project(point)`（模型点 → 舞台像素）。
- 步骤：

## 硬边、倒角与线（Z1 复刻样板定）`[kit]`

- 参考实现：`blender/kit/finish.py` 的 `hard_edges` / `finish`；网页 `30-lines.js` 里带 `part.edges` 的分支。
- 做法：所有零件收尾都调 `finish(obj, bevel=1.5～4 cm（小件按尺寸）, segments=2)`：先记下折角 > 30° 的硬边，再做两段倒角；线只从这些母版硬边来，位置挪到倒角圆弧中点（离原棱 `w·(1 − sin(α/2)) / cos(α/2)`），两侧法线取原面法线——一条棱只出一条线，不出双线。曲面件（`curved`）不记折边，网页按曲面轮廓取线。
- 线的深度让出量随取景缩放（`30-lines.js`：`bias / zoom`，下限 1.5 mm）：特写里贴着蒙皮的零件不再透线。
- 多材质对象导出成几个图元时，硬边只挂第一个图元（`meshpack.mjs`），否则线画三遍、显得过亮。

## 剖面封口、蒙皮剖面带与结构（Z1 复刻样板 R3 定）`[kit]`

- 参考实现：`10-materials.js` 背面分支（`uCap`）、`cutMaterial(material, section)`；几何母版 `section.py`（剖面带）、`interior.py` 的 `structure()` / `frame_at()` / `harness()`。
- 被剖切面切开的东西分三种（零件属性 `section`）：`"cap"`（默认，实心件）= 背面画成剖面：本体最亮档再亮一档的平色 + 屏幕空间 45° 极淡细斜线（7 px 一道，压暗 14%）；`"inside"`（空心蒙皮 nose.body）= 暗内壁（深蓝黑 `palette.inside`）；`"shell"`（座舱盖玻璃这种实心建模、实为薄壳的件）= 背面照常着色、半透明。
- 蒙皮自己的剖面不靠背面，而是几何母版直接给一圈 4 cm 厚的剖面带（`section.top / brow / brow.rear / slot / canopy / aft / keel`），沿剖切面两侧各 2 cm，剖视时切掉一半露出实心面；座舱盖玻璃的剖面带 1.2 cm、玻璃材质（青色细边）。眉骨后壁中间开遮光盾槽，上下两块金属衬板，盾收在中间。
- 结构：隔框站位 `FRAME_S`（K1 零件表里的框 + 每约 0.5 m 补齐），框 = 沿内表面内缩的一圈板（`frame()`），近侧一半被切掉、切口是实心剖面；座舱开口段只做 U 形；中线处背脊、龙骨各一块连接块（顺屋面坡度，不穿出）；远侧四根角材桁条；龙骨、背脊两根工字纵梁跨剖切面（剖开是实心工字截面）。线束：上下两根主干 + 每道框一根支线，两端插头、两只卡箍。
- 自检：`section.containment()` 每个内部件顶点都在截面内（座舱段放宽到座舱盖下），build 打印“穿出蒙皮”件数，必须为 0。
- R4 远侧内衬与远近分档（作者：K1 的内壁是成片浅灰壁板）：每两道框之间、远侧四个切面各一块 4 mm 壁板（`int.liner.*`，材质 `liner`，离框 2.5 cm、离棱 2 cm、贴内表面 6 mm，L2 线），座舱侧壁也用 `liner`。壁板材质带 `fill: 0.85`（`10-materials.js` 的 `uFill`）：按 0.85 混向“从剖切口照进来的平光”（B：基色 × (0.6 + 0.4 n·v)；A：第三档 × (0.8 + 0.2 n·v)），朝下的远侧屋面也读成浅灰（同一个 `fill` 也用在机腹 0.6——朝下的鳞片瓦在 B 里比地台还暗；光窗虹膜叶片 0.4——在烟晶角膜后面）。剖视时 `uDepthFade` = 1：零件按模型坐标 −y（离剖切面多远）压暗，0.05 m 起、0.6 m 到底，最多压 38%；线最多淡 50%。
- 常见错误：壁板直接用结构材质（朝下的切面在 B 里接近黑，读成骨架而不是壁板）；壁板加螺钉（远侧压暗后看不见，白占模块面数）；壁板烘顶点 AO（八个顶点的板被前面的件一挡就整块发黑，要 `aoFlat: True`，与口盖薄板同）。

## 人体：开源基础网格摆姿（Z1 复刻样板 R3 定，WORKFLOW「人体不用基本形拼」）`[kit]`

- 参考实现：`blender/zl/pilot.py`；数据 `blender/assets/makehuman/`（CC0，THIRD_PARTY_NOTICES 有记录）。
- 摆姿：MakeHuman 默认骨架（关节 = 关节辅助体顶点的平均）+ 默认权重做线性蒙皮。肢体分段，每段的旋转 = 静止标架 → 目标标架（段轴 + 铰链轴；大腿 / 小腿、上臂 / 前臂共用一根铰链轴，膝肘不拧麻花），膝、肘用两段 IK（极向：膝朝上、肘朝外下），手指按节绕“食指 → 小指”轴弯向掌心。接口是一张 `seat` 表：座椅参考点、椅背角、坐垫 / 椅背面、膝内角、脚的指向点、握把中心、手轴与指节方向、掌心朝向、腰带扣点。接触：臀贴坐垫、背贴椅背，平移后重解 IK，迭代到 0.5 mm。build 打印头盔顶离座舱盖内表面的距离（要 4～8 cm）。
- 服装：整身沿法线外移 5 mm；分片按静止姿态里的平面切（袖根、肘、腕、膝、靴口、领口、前后中线）再按相邻面多数决平滑三轮——分片边界就是接缝线，直而不锯齿；气囊、护膝是外层贴片（再高 8～16 mm）；靴头用脚的凸包（不出脚趾）+ 鞋底；挽具是扁织带（宽 4～5 cm、厚 5 mm），折线加密后投到躯干体表（只在躯干 / 大腿上找，不吸到手臂上）再平滑；头盔按 DESIGN 9.1.1 重做（眉骨、窄面罩、收起的暗琥珀遮光面罩、盔脊、铰链、颈环），头部网格不建。
- 握把、脚蹬随人：侧杆 / 油门放在半躺的人手够得着的地方（`GRIPS`），脚蹬贴在摆好的脚掌下——不要反过来让人去够 K1 上画的位置。
- R4 服装壳（作者：服装不能透出肌肉，接缝去锯齿）：① 先平滑身体——`smooth_body()` 按段加权（躯干 1.0、大腿 / 上臂 0.9、前臂 0.7、小腿 0.7，手脚头 0）：拉普拉斯收缩 40 轮抹掉胸肌腹肌，再把原形相对收缩形的法向位移低通 80 轮后加回去（保住体量、不保细节）；摆姿后再做两步：`delta_mush()`（静止 / 摆姿各平滑 30 轮，细节差量按局部标架搬过去——线性蒙皮在肩、胸前鼓出的包与折棱抹掉）、`bridge_grooves()`（躯干每点与 5 cm 内的二次曲面比，低于曲面的沿法线推出 0.8 倍，迭代 4 轮——布面跨过胸大肌下缘那道 5 mm 横沟；沟上的胸肌在高光里最像“透出肌肉”）。加大收缩轮数没用：躯干变细，胸前反而更像两个鼓包；② 再沿法线外扩 7 mm 成完整服装壳；③ 手套、靴、领口用 bmesh 平面切开（`bisect_plane`），切口是直的；④ 接缝线不再取分片边界，而是“网格与平面的交线”（`plane_segments()` 逐面求交、首尾串成折线），肩缝只取靠近手臂轴 7.5 cm 以内的一段，所以肩、腋下没有锯齿；⑤ 胸前铭文「銜燭」（繁体）用 Blender 字体曲线转网格（文泉驿正黑），贴在胸前（离中线 4 cm、拉链一侧）服装表面外 4 mm，字高 2.4 cm（1.8 cm 在 7× 里读不出）。
- R4 头盔（DESIGN 9.1.1，要一眼可见）：盔壳椭球 0.138 × 0.126 × 0.146 m；盔顶前凸的眉骨是一块楔形（框体材质，向前凸出 25%）；面罩窄（左右 ±40°、上下 −30°～+8°，玻璃）；收起的暗琥珀遮光面罩在面罩之上（10°～17°，`visor` 色板）；盔脊、两侧铰链 + 镀铬螺栓；镀铬颈环（车削体 + 两只锁扣）。

## 画法 B：金属质感（默认画法，作者 2026-10-15 定）`[kit]`

- 参考实现：`10-materials.js` 的 `uLook` 分支（`envRadiance` / `envIrradiance` / `camDir`）、build.mjs 的 `PBR` 表与 `--look=metal`、`__arcseq.look({ mode: "metal" | "lines" })`。
- 做法：同一套材质着色器里多一条分支：基色取色板第 4 档、换到线性再乘增益；工作室环境光是解析的（地暗顶亮的渐变 + 四块柔光箱：左上前主光、顶条、右后轮廓条、前下补光），固定在相机坐标里；粗糙度越大柔光箱越软越暗；菲涅尔用 Schlick；AO（顶点 + 贴图）只压漫反射与一部分镜面；机身蒙皮用烘焙的物体空间法线 + 粗糙度贴图。线条降一级（三级不透明度乘 `DATA.metal.lines` = 0.55 / 0.45 / 0.3）；发光照旧走选择性泛光。
- 常见错误：把环境光写在世界坐标（转台转一圈高光跟着转、俯视时灯位乱）；B 的贴图进了 A 的页面（白白多 0.5 MB）。
- R3 加强（作者：B 看不出区别）：① 盒投影反射——反射方向按片元位置偏一点（环境当成转台四周约 6 m 的盒子），大块平切面上才有明暗渐变，金属感主要靠它；② 环境对比加大：地更暗、顶更暗，主光 7.0、副光 2.2（两侧分得开），轮廓条 4.6；③ 轮廓光：`(1 − n·v)^4`，朝相机左后上方的边更亮，冷色；④ 烘焙 AO 在 B 里取 1.8 次幂，压漫反射全部、镜面 85%。机身 PBR 改为金属度 0.62、粗糙度 0.34、增益 3.6。验收看 `AB-oblique.png`（3/4 斜视并排：外形通电、剖视）。
- R4 定稿：B 是默认画法，`node src/figure/build.mjs` → `dist/index.html`（B，带 B 的贴图），页面「图纸」按钮运行时切到 A（`__arcseq.look({ mode })` 只换 uniform）；`--look=lines --out=dist/drawing.html` 出只有 A 的审图页。B 的线：外轮廓浅色、结构线与分割线是深色细缝（`DATA.metal.lineColor` / `lineAlpha`），读成刻出来的缝。
- R4 反射条纹（右侧面板一道道的暗条纹）：根因是**蒙皮的顶点 AO**——切面只有几个大三角形，滑轨滚轮旁一个顶点被压暗，暗色沿长三角形拉成竖条，B 的 AO 1.8 次幂又放大了它（`__arcseq.look({ ao: 0 })` 一关就没）。做法：带细节贴图的蒙皮（`skin = "skin"`）与贴面薄板 / 壁板（零件属性 `aoFlat: True`：口盖、剖视内衬）顶点 AO 写 1，AO 只用 `detail_texture` 逐纹素烘的那张（`bake.vertex_ao`）。另外贴图法线只在真有起伏处用：`mix(n, nm, smoothstep(0.03, 0.07, |nm − n|))`，平整处 8 位量化误差不在清晰反射里显成细纹。
- 常见错误：大面积低面数的件用顶点 AO（任何细节都会被拉成渐变条）；查条纹先逐项关 `look({ ao, detail })` 再改着色；与蒙皮共用材质、但没有 uv 的件（口盖板、鸭翼、眉骨、鳞片瓦）去采样蒙皮的细节 / PBR 贴图——uv 全 0 取到贴图角上的填充像素，物体空间法线“朝上”，斜面上的件整块被照错。引擎做法：`20-model.js` 里没有 uv 的零件一律用 `plain(material)`（关掉两张贴图的副本）。`[kit]`

- Z2 R1 石墨灰（作者：R4 的浅蓝灰读成哑光塑料）：机身 `PBR.hull` = 金属度 0.8、粗糙度 0.34、增益 0.75；机腹 `belly` = 0.6 / 0.4 / 2.4。基色压暗、金属度提高，明度交给环境反射——方位 30° 上表面灰度约 66（A 约 50，地台 29），大平切面上留一条反射渐变。验收：上表面 60～75、机腹比地台亮 15 以上，300 px 缩略图里机体仍与地台分开。
- 常见错误：只把增益压低、不提金属度——整机变成一块平的深灰塑料（没有反射渐变）；反过来只提金属度不压增益——仍然是浅色。

- 输入：作者用 GPT 编辑出的分色块面图（八类纯色 + 黑描边）、`<图名>_分色.calib.json`（分色图 → 原图，横竖分别缩放）、`<图名>.calib.json`（原图 → 机体米制：锚点、px/m、竖向映射分区）。
- 脚本：`scripts/k1-parts.py`（`.venv/bin/python`，要 scipy、scikit-image）。分类按 HSV 色相，阈值见 `classify()`；块状零件 = 每类 4 邻接连通块（黑描边隔开同色件），最小面积按类；

- 输出列：编号、名称、类别、区段、站位 s、y、z、长宽高、基本形、材质、固定在、现有零件、来源图、把握度、y 来源、原图像素框、路径（管：s:z;…）、备注。“现有零件”按同类包围盒 IoU（管按路径落点）对到几何母版，缺的就是待建清单。
- 已知错误（README 里列的）写进 calib 的 `known_errors`（原图像素框 + 说明），对应的行标“忽略”，不建。
- 交审三张图：PARTS-overlay（全部叠回原图）、PARTS-split（分类别）、PARTS-status（已有 / 缺）。作者确认后才按表建模。
- 细节：罐的判定看包围盒四角（各 12%）几乎空、长边中段满；管的骨架分支短于 16 px 是毛刺；管带“管网”号（同一连通蓝块）；“现有零件”除了同类 IoU，还认“装在一个更大的紧凑现有件里”（细长件的包围盒不算），标“并入 …”。

## 化剑转轴与逐姿态检查（Z2 定）`[kit]`

- 适用于：一切化剑 / 展剑要动的件（扇骨、翼尖鳍、鸭翼、边条、垂尾、进气门），以及以后 Z4 的解锁件、锁销、盖板。
- 参考实现：`blender/zl/airframe.py`（几何、关节、步骤都在这一个文件）：`wing()`（扇骨 = C2 平面形 `PLANFORM` 按扇形角 `_wedge` 裁出、`_slab` 加厚）、`tail()`、`fillet()`、`intake_door()`、`mirror_joint` / `mirror_part`、`sword_steps`；`blender/check.py`（逐姿态检查）；`scripts/z2-review.sh sword`（叠图 C3、逐姿态正交俯视与斜视、缩略图）。
- 做法：
  1. 零件只建左侧（`.l`），写 `joint: "<关节名>"`；关节写成 `{ name, type: "hinge", point, axis, range, parent?, note }`，**正值 = 朝剑形态转**；右侧由 `mirror_joint`（点 y 取反、轴按赝矢量 `[-ax, ay, -az]`）和 `mirror_part` 生成，左右同一组角度就是镜像动作。
  2. 挂在别的动件上的（翼尖鳍挂在前缘扇骨上）写 `parent`；关节点、轴都按**静止姿态**的坐标写，引擎按父子组嵌套自动复合。
  3. 在 `sword_steps` 加一步 `{ joint, to, span: [起, 止] }`：控件值 0 → 1，每步在自己的区间里 smoothstep；相邻步骤可以重叠，但**会扫过同一片空间的两件要错开**（后缘边条先折、扇骨后收；翼尖鳍先下折到竖直、再随扇骨收）。
  4. 跑 `.venv/bin/python blender/check.py --poses 41`：41 个姿态里不同刚体组的零件两两 `BVHTree.overlap`（同一关节链的件相对不动，不查；固定件之间的嵌入——轮毂、轴套、喷口——不算）；相邻姿态位移渐变（跳变检测）；剑形态里没有件整件藏进机身；最后列出每个动件全程的最小间隙。**0 穿模、0 跳变、0 藏进机身**才进下一步。
  5. `blender/build.py --fast` + `node src/figure/build.mjs --assets=dist/fast --out=dist/fast.html` 看形，`PAGE_A=… PAGE_B=dist/fast.html LOOKS=B sh scripts/z2-review.sh <目录> sword` 出逐姿态图；定稿再全量烘焙。
- 间隙约定：叠层件层间 4 mm（扇骨厚 3.6 cm、层距 4 cm）；动件离机身 ≥ 1 cm（鸭翼离下切面 4 cm 的缝就是“棱线槽”）；铰线放在零件根部的底面内沿，折下时零件厚度朝外。
- 常见错误：轴向反了（零件往机身里折——check 从 v≈0.1 起就报穿模）；只看收拢后、不看中间姿态（翼尖鳍在收扇途中扫过后缘边条，只有逐姿态才查得出）；放平的进气门比斜板长（放平后顶到唇口）；在 `z2-review.sh` 还在跑时改它（sh 边读边执行，后面的命令会读乱）。
- `[Codex]`（Z4）：照 DESIGN 10 的六个层次给每个化剑件加解锁 / 锁销 / 盖板（新件照上面 1～4 步接进关节与步骤，check 全过再交）；扇骨“肋”与轮毂的细节在 Z3 体积层定样后照样铺。

## 外部模型（Tripo 等）的导入、检查与保法线（2026-10-15 踩坑后定）`[kit]`

**事故**：检查 Tripo 头盔时，为了统计四边面，渲染前先用 `bmesh.ops.join_triangles` 合并了三角面再出检查图。网格一改，GLB 自带的自定义法线（Tripo 靠它表达平面与硬棱）就对不上，平整块面被渲成坑洼、发糊，误判成“模型软、后脑歪扭”，作者在 Tripo 里看是清楚的。
**规矩**：
1. **检查图只用原样导入**：`import_scene.gltf` 之后不做任何改拓扑的操作（合并三角面、减面、重拓扑、`bmesh` 往返）再出图；统计面数、四边面比例在副本上做，不拿副本出图。
2. 每张检查图旁边配一张 **Tripo 自带查看器的同角度截图**作对照；两者观感不一致，先查自己的导入和渲染，再下结论。
3. 精修时要改拓扑：先把原模型法线烘成法线贴图，或改完后 `shade_smooth_by_angle`（约 30°）重设锐边，再与原样渲染并排比一次。
4. GLB 会把四边面三角化；要保留四边面拓扑就导 FBX，不要在 GLB 上“合并回去”。
5. 作者也可以在本地 Blender（Tripo DCC Bridge 直送）打开原模型作最终对照。
